### 자동 대여 장면의 정확한 설명

현재 스마트재고 요청 계약은 **가까운 재고 매장들에 요청하고 먼저 승인한 매장이 제공**하는 방식입니다. 외부 자동화가 다른 방식을 사용한다면 담당자가 실제 계약을 확인한 뒤 내레이션을 맞춥니다. “가까운 한 매장으로 자동 전송”이라는 표현은 실제 선택 방식이 확인된 경우에만 사용합니다.

후보 매장 검색으로 대여 생성이 지연될 수 있습니다. 실제 요청이 생성된 뒤 조회 장면을 촬영하거나 대기 구간을 편집할 수 있으나, 생성되지 않은 요청을 새로고침으로 생긴 것처럼 연결하지 않습니다. 실패·timeout 뒤 즉시 반복 요청하지 말고 기존 실행·생성 행부터 확인합니다.

- 브리핑의 “이전 저장 상담”과 왼쪽 “현재 위험 신호”를 자막 또는 화면으로 구분합니다.

- 외부 수신·DB 생성·예약·대여·문자 발송의 미검증 항목이 남으면 전체 자동화가 완료됐다고 표시하지 않습니다.

### 이름과 화면용 완료 자료

- 기존 예시 고객·직원·매장명은 이미 자연스러운 이름으로 표시됩니다. 기존 ID·연결·원본 이름은 유지합니다.
- 실제 저장 이름 중 확인된 `테***객`만 고객 ID에 따라 `고객 9999`처럼 중립 표시합니다. 브리핑·저장 고객·예약·체감가 고객 선택에 같은 표시 함수를 적용합니다. 일반 마스킹·비공개 고객·확인되지 않은 문자열은 그대로 유지합니다. 표시명 검색도 기존 검색값과 함께 지원합니다.
- `DEMO-R001`은 원래 완료 상태였으며, 이제 입력 기준일의 10:30 시작·10:50 완료, 직원 이지은의 명시적인 가상 결과를 가집니다. 완료 건수·예약 ID·다른 예약은 바꾸지 않습니다. 이 요약은 화면용으로 작성한 예시이며 실제 AI 요약이나 DB 기록이 아닙니다.
- 마케팅에는 화면용 예시라는 출처와 문자 미전송·새로고침 초기화 안내를 유지합니다. 확인한 수정 메시지가 목록과 처리 기록에 동일하게 표시됩니다.

### 직접 확인한 범위와 촬영 순서

1. **체감가:** 공개 상품 화면에서 고객 없이 `초이스 90 디즈니플러스`를 선택하면 저장 월정액 90,000원입니다. `정액결합할인`의 조건이 미확정이면 할인과 소계를 보류합니다. 가족/인터넷 조건 충족·회선 2개를 입력한 저장 구간에서는 할인 7,000원, 통신요금 소계 83,000원입니다. `Galaxy S26 Ultra / 512GB / 티타늄 실버` 저장 일시 가격은 1,984,400원이며 월할부와 최종 총부담은 확인 필요입니다. 이는 저장 자료 계산 검증이며 KT 최신 공식 가격 검증이 아닙니다.
2. **마케팅:** 격리된 로컬 빌드의 기본 완료 상담을 열고 메시지를 수정합니다. 내용 확인 전에는 처리 버튼이 비활성이고, 확인 후 다시 수정하면 재확인이 필요합니다. 안내 처리 후 메뉴를 이동해 돌아와도 메시지·확인자·처리자·최초 시각을 유지합니다. 새로고침하면 기본 예시로 돌아오며 처리 상태는 초기화됩니다. 촬영도 이 순서를 따릅니다.
3. **실제 통화·사전 브리핑:** 승인된 실제 통화로 준비하고 실제 저장 성공 및 이전 기록을 대조합니다. 화면용 마케팅 결과를 실제 수신 통화의 저장 결과로 연결해 설명하지 않습니다. 고정 테스트 요약은 계속 정상 요약에서 제외하며 새 요약을 만들지 않습니다.
4. **대여·문자:** 실제 예약→자동 대여 연결, 승인된 실제 문자 배달 증거가 확보된 뒤 해당 장면을 촬영합니다. 현재 화면의 ‘안내 처리’를 SOLAPI 발송 장면으로 대신하지 않습니다.

검증: 자동 908/908, 프런트·백엔드 타입 검사·production build 통과. 격리 브라우저에서 마케팅 처리·새로고침·고객 표시/검색·9개 기본 route를 확인했고, 공개 서버에서는 상품 계산과 재고 조회만 확인했습니다. 실제 통화·DB write·SMS·자동 대여 생성·외부 workflow 변경은 수행하지 않았습니다. 독립 HTML은 화면용 예시 미리보기이며 실제 저장 조회/Retell/SSE 검증 환경을 대신하지 않습니다.

### 최신 main과 통합한 조회 조건

이후 main `a01a5b7`에 반영된 저장 고객 조회 인증을 함께 보존했습니다. 저장 고객 목록·상담 요약은 [조회 계정 안내](STAFF_CUSTOMER_READ.md)에 따라 로그인 후 허용 매장 범위에서 확인합니다. 위 표의 공개 저장 고객 제한은 점검 당시 상태이며, 저장 예약 등 다른 조회의 접근 제한은 계속 유지합니다. 통합 검사 972/972와 프런트·백엔드 타입 검사·build를 통과했으며, 실제 음성·DB write·문자 발송 검증을 대신하지 않습니다.

## 승인된 시연 고객 표시 — 2026-10-07

- 사용자가 지정한 시연 고객 한 명의 실제 DB 이름만 변경했습니다. 기존 고객 ID·동의·매장 연결·상담5건을 유지하며 신규 고객·상담·예약을 만들지 않았습니다. 저장 자료의 이름은 기존 서버 마스킹을 사용합니다.
- 실시간 SSE에는 이름 필드가 없으므로 승인된 시연 ID 한 개만 중앙 표시 helper로 같은 마스킹 이름을 사용합니다. 다른 고객의 이름·ID·조회/선택 값·권한을 덮어쓰지 않습니다. 향후 일반 고객 이름 조회 기능은 이 표시 예외와 별도입니다.
- 시연 고객의 목록·실시간 카드·브리핑·상담 상세에 불필요하게 중복 표시되던 고객/통화 기술 ID는 기본 화면에서 감추거나 접습니다. 점검할 때 식별 정보 펼치기로 원본 연결을 확인할 수 있습니다. 점수·전문·시각·전송 상태는 바꾸지 않습니다.
- 화면 수정은 해당 버전의 실제 배포 뒤 새로고침해야 반영됩니다. 진행 중 고객 통화 화면은 새로고침하지 않습니다. 운영 적용과 리허설 여부는 STATUS.md에 기록합니다.
- 웹훅 비밀값 노출을 막기 위해 새 서명키/짧은 JWT 전환이 필요합니다. 설정 입력·발행·배포와 새 통화 검증을 완료한 뒤 촬영합니다. 기존 실행 기록의 삭제나 실제 SMS 수신 확인은 이번 이름 변경으로 해결되었다고 표현하지 않습니다.
