## 과거·현재 통화를 혼동하지 않는 기준

왼쪽 위험 신호·전문은 **현재 선택한 통화**이고, 오른쪽 사전 브리핑은 **그 통화 시작 전에 끝난 저장 상담**입니다. 현재 통화와 같은 `call_id` / `consultation_id`는 이전 상담에서 제외합니다.

- 현재 통화가 60점으로 종료됐더라도 그 통화의 오른쪽에 **이전 통화 20점**이 표시되는 것은 조회 기준상 정상입니다. 오른쪽의 20점을 현재 통화의 잘못된 최종 결과로 판정하지 않습니다.
- 다음 통화에서는 앞선 60점 상담이 같은 고객·같은 매장에서 가장 최근의 유효한 완료 상담으로 조회될 때 **이전 60점**을 표시해야 합니다. 그 사이 다른 완료 통화가 있으면 해당 최신 기록이 선택될 수 있으므로 점수만 보지 말고 상담 ID·종료 시각을 대조합니다.
- 같은 `customer_9999`로 이어지는 통화의 고객 연결을 유지합니다. 화면을 채우려고 다른 고객 ID의 이력을 섞거나 이름이 같다는 이유로 고객을 합치지 않습니다.
- 과거 확정 위험 점수는 현재 정책으로 다시 계산하지 않습니다. 현재 통화에 이전 횟수나 점수를 더하지 않습니다.
- 일반 공개 저장 예약·고객 API의 `REAL_DATA_ACCESS_RESTRICTED` 보호는 유지합니다. configured demo customer에 대한 실시간 브리핑 예외를 전체 예약 조회 허용으로 확대하지 않습니다. 공개 예약 화면이 제한되어 있으면 담당자가 승인한 조회 환경을 준비해야 하며, 촬영을 위해 보호를 끄지 않습니다.

### 자동 대여 장면의 정확한 설명

현재 스마트재고 요청 계약은 **가까운 재고 매장들에 요청하고 먼저 승인한 매장이 제공**하는 방식입니다. 외부 자동화가 다른 방식을 사용한다면 담당자가 실제 계약을 확인한 뒤 내레이션을 맞춥니다. “가까운 한 매장으로 자동 전송”이라는 표현은 실제 선택 방식이 확인된 경우에만 사용합니다.

후보 매장 검색으로 대여 생성이 지연될 수 있습니다. 실제 요청이 생성된 뒤 조회 장면을 촬영하거나 대기 구간을 편집할 수 있으나, 생성되지 않은 요청을 새로고침으로 생긴 것처럼 연결하지 않습니다. 실패·timeout 뒤 즉시 반복 요청하지 말고 기존 실행·생성 행부터 확인합니다.

## 촬영·편집 원칙

- AI 응답·조회 대기 구간은 편집할 수 있으나, 존재하지 않는 예약·대여·문자를 생성된 것처럼 연결하지 않습니다.
- 고객의 녹음·음성 분석 동의 응답을 분명히 확보합니다. 단발성 욕설 이후의 상담 지속과 명확한 동의 거부·종료 요청 처리 조건은 별개입니다.
- 음성 측정은 정상 종료까지 유지합니다. 고객 페이지 이동·새로고침·마이크 중지는 촬영 중 하지 않습니다.
- 브리핑의 “이전 저장 상담”과 왼쪽 “현재 위험 신호”를 자막 또는 화면으로 구분합니다.
- 공유 캡처에는 API 키·access token·Authorization·Webhook 주소·직원 연락처를 포함하지 않습니다. 불필요한 고객 정보와 기술 ID는 가립니다.
- 외부 수신·DB 생성·예약·대여·문자 발송의 미검증 항목이 남으면 전체 자동화가 완료됐다고 표시하지 않습니다.
