# 체감가 계산 — 준비된 n8n 견적 정책 연결

사용자가 제공한 6개 입력과 기존 n8n 결과를 앱의 상품관리 → 체감가 계산에서 동일하게 표시합니다. 가격과 월정액은 현재 DB에서 읽고, 할인표·할부 계산·결합 가정은 팀이 준비한 n8n 정책을 재사용합니다. 공식 통신사 정책을 실시간 조회하거나 실제 가입 자격을 확정하는 기능은 아닙니다.

## 입력과 정책 범위

입력 순서는 단말기(`product_id`), 요금제(`plan_id`), 결합(`bundle_id`, 선택 안함 가능), 할부개월(`installment_months`), 약정개월(`contract_months`), 할인종류(`discount_type`)입니다.

- 할부: 24개월 또는 일시불(1). 약정: 24개월.
- 할인종류: `PLAN_DISCOUNT` 요금할인 / `DEVICE_DISCOUNT` 기기할인.
- 요금할인은 선택약정25%와 기종별 추가 단말 할인을 적용합니다. 기기할인은 준비된 공통·추가 단말 할인표를 적용하고 선택약정은0원입니다.
- 연5.9% 할부의 매월 이자와 정규 월 납부액을 원 단위 내림하고, 마지막 회차에서 남은 원금을 정산합니다. 총액을 화면의 반올림된 월평균×개월로 역산하지 않습니다.
- 9만원 외 요금제는 준비된 기종별 단말 할인표를 그대로 사용하는 시연 계산이라는 안내가 표시됩니다.
- 6개 입력만으로 결합 조건을 확정할 수 없어 원본과 같은 가족 회선·500M 인터넷·36개월 인터넷 약정 등의 시연 조건을 가정합니다. 결합 가정과 자격 미확인 안내를 결과에 표시합니다.
- `bundle_001`에는 모바일 할인 DB 규칙이 없으므로 원본의 정액 시연 정책을 적용합니다. 인터넷·TV 할인은 모바일 요금에 더하지 않습니다.
- 준비된 표에 없는 기종은 `PRICE_POLICY_UNAVAILABLE`로 계산을 중단합니다. 할인0원으로 임의 견적을 만들지 않습니다.

## 승인 예시

```json
{"product_id":"product_001","plan_id":"own_plan_001","bundle_id":"bundle_001","installment_months":24,"contract_months":24,"discount_type":"PLAN_DISCOUNT"}
```

DB 기준 단말1,254,000원·요금90,000원에서 다음 값이 나옵니다.

| 표시 항목 | 금액 |
|---|---:|
| 예상 월 납부금액 |112,036원|
| 월 단말 할부금 |51,536원|
| 할인 후 월 통신요금 |60,500원|
| 단말 할인 총액 |90,000원|
| 선택약정 월 할인 |22,500원|
| 모바일 결합 월 할인 |7,000원|
| 24개월 총 할인 혜택 |798,000원|
| 할부수수료 총액 |72,871원|
| 약정기간 총 체감가 |2,688,871원|
| 월평균 체감가 |112,036원|

정규 납부액은112,036원이고 마지막 회차는112,043원입니다. 이7원 정산을 총액에 반영합니다. 일시불은 첫 달과 다음 달 이후 납부액을 구분합니다.

## 구현과 보호 범위

`server/effective-price-policy.mjs`는2026-10-07 16:30에 n8n의 `Price Calculation` 노드에서 읽은 계산 정책의 정적 JavaScript 복사본입니다. 원본 SHA256은 `D299707AF5FD0AD0FA27FB93C0780115C6D74B6B89616CC5F05AEAA7CCCC8889`입니다. 입력 진입점/반환 객체를 일반 함수로 바꾸고, 정책 미등록 오류를 안전한 코드로 구분했습니다. 동적 코드 실행·n8n 자격증명·워크플로우 전체 파일은 포함하지 않습니다.

이 정책 복사본은 원본 동작 보존을 위해 JavaScript 정적 타입 검사를 제외하며, API 경계의 입력·DB 컬럼 검증과 정책 결과 테스트로 검증합니다. 후속 정책 변경은 n8n과 이 복사본을 함께 검토해야 합니다.

`POST /api/effective-price`는 새6조건 요청에 `n8n-quote-v2`와 `quote`를 반환합니다. 기존 `db-fixed-mobile-v1` 요청·응답은 유지합니다. 사용자가 가격·지원금·수수료를 임의 입력할 수 없으며 서버가 DB의 명시 컬럼만 조회합니다. 고객 지정 시 기존 매장·동의·공개 사이트 보호를 유지합니다. 새 화면은 고객을 지정하지 않고6개 견적 조건만 전송합니다.

DB 쓰기·스키마·RLS·실제 고객 기록·통화 저장·웹훅 인증·문자 발송·n8n 운영 발행은 이번 계산 변경에 포함되지 않습니다.

## 검증

- 사용자 예시의 월액·할인·수수료·총액 전체 일치, 마지막7원 정산, 일시불, 기기할인, 결합 없음, 가정 안내, 미등록 정책 중단, 입력 객체 불변성을 자동 검사합니다.
- 실제 catalog 읽기 결과12단말×51요금×5결합×2할인종류의6,120조합 중5,100조합을 계산했습니다. 나머지1,020조합은 원본 표에 없는 iPhone18/18Plus 두 기종으로 계산을 중단했습니다. 실제 가입·결제 검증과 구분합니다.
- 전체 테스트·타입 검사·production build·독립 HTML·브라우저 결과는 `STATUS.md`에 기록합니다.
