# Retell 통화 중 재고 조회 호환 보완

## 적용 대상

- n8n `KCM Project`의 `Retell Query Adapter` Code 노드(모든 항목을 한 번에 실행).
- 실제 재고 문의 통화에서 확인한 `UNSUPPORTED_SQL_SHAPE` HTTP 400의 원인은 입력 SELECT의 컬럼·JOIN 순서·용량 조건이 기존 네 가지 허용 형식과 달랐던 것입니다.
- 이 폴더의 JavaScript는 n8n 노드용 자료입니다. KCM 프런트/서버에서 입력 SQL을 실행하는 기능이 아닙니다.

## 보완 내용

- 기존 네 SELECT 형식과 구조화 `lookup` 요청을 보존합니다.
- 실제 실패한 재고 SELECT 다섯 가지 형식만 추가로 인식합니다. 입력 SQL 전체를 DB에 전달하지 않고 로컬 고정 SELECT와 별도 값 목록으로 바꿉니다.
- `available`, `available_qty`, 원본 재고 수량 컬럼을 요청별로 유지합니다.
- 용량이 있으면 유효한 양의 정수인지 확인합니다. 없으면 `null` 매개변수로 해당 모델·색상의 용량별 옵션을 조회합니다. 512GB 등 임의 용량을 지정하지 않습니다.
- 추가 SQL, UNION, 주석, 함수, 범위 조건 제거와 알 수 없는 조회 형식은 계속 거부합니다.
- SQL 문자열과 구조화 조회를 동시에 지정하거나 내부 조회 키로 검사를 우회할 수 없습니다.

## 확인 방법

```powershell
node --test docs/n8n-repair/retell-query-adapter.test.mjs
npm.cmd run check
```

- 노드 검사 14/14 통과: 기존 8개 유지, 실제 실패 형식·용량 조건·값 바인딩·차단 회귀 추가.
- 기존 앱 검사 972/972, 프런트·백엔드 타입 검사, production build 통과.
- 운영 구조화 조회에서 S26 Ultra 512GB 티타늄 실버의 가용 수량 0대를 확인했습니다. 이는 조회 오류가 아니라 당시 조회된 재고입니다.
- 실제 통화 재검증은 별도입니다. 용량 미지정 응답은 여러 옵션일 수 있으므로 Agent가 임의 용량으로 단정하면 안 됩니다.

## 적용 주의

- 현재 workflow를 백업한 뒤 이 노드 코드만 변경합니다. 전체 workflow JSON을 덮어쓰거나 모든 노드를 실행하지 않습니다.
- DB credential·스키마·기존 상담 저장·예약·대여·SMS 설정은 이 보완에서 변경하지 않습니다.
- n8n Publish는 같은 workflow의 대기 변경 전체를 적용합니다. 공동 편집자의 변경과 상담 저장 webhook 인증 호환을 확인한 뒤 진행합니다.
- 이번 조회 확인은 SELECT만 실행하며 재고 조정·대여 생성·예약·상담 저장·문자 발송을 수행하지 않습니다.
- 전체 workflow 백업에는 설정과 credential 참조가 있으므로 Git 제외 `.cache`에만 보관합니다. 실제 webhook 주소·키·응답 전문을 이 폴더에 기록하지 않습니다.

## 현재 적용 상태

최종 코드가 n8n 편집본에 반영됐습니다. 상담 저장 `Start` 노드에 공동 편집자가 추가한 Header Auth와 현재 KCM 전송의 호환 확인을 기다리고 있습니다. 확인 전에는 Publish와 실제 통화 재검증을 완료로 보지 않습니다.
