## 구조와 조회 시점

직원 홈의 실시간 AI 상담 → 실시간 상담 보기에서 기존 대화 모달을 엽니다.
좌측은 기존 현재 위험 신호와 transcript, 우측은 저장된 과거 상담의 사전 브리핑입니다.
현재 통화 점수·신호는 브리핑 데이터와 별도이며 합산하거나 재계산하지 않습니다.

`LiveCallBriefing` → `GET /api/live-briefing/:customerId?call_id=:callId` →
Backend의 통화/고객/매장 검증 → 기존 SELECT 전용 Supabase provider → 최소 DTO.

`call_id`는 조회 문맥을 검증하기 위한 선택 항목입니다. 브라우저는 현재 선택 통화의 ID를 전송합니다.
서버는 해당 ID의 메모리 통화 기록에서 고객·매장·최초 시작 시각·상담 ID를 가져옵니다.
브라우저가 임의 시작 시각이나 매장/제외 ID를 지정할 수 없습니다.
동일 통화/고객의 transcript·위험 신호·상태 갱신은 브리핑 재조회 조건이 아닙니다.
새 통화/고객 선택, 패널 새로 열기와 수동 ‘다시 조회’에서만 요청합니다.
고객 ID가 없으면 조회하지 않습니다. AbortController, 요청 세대 번호와 선택 ID 검사로
닫기/통화 전환 후 늦은 응답이 다른 고객 패널에 표시되는 것을 막습니다.
React StrictMode의 즉시 cleanup에는 네트워크 요청 전 취소를 적용합니다.
요청과 응답 본문에 10초 제한을 적용하며 upstream 오류 원문은 표시하지 않습니다.

## 과거 상담 선택

- 서버 환경의 현재 매장 + 요청 고객 + `status=완료`인 상담만 조회합니다.
- 진행 중/오류 통화와 종료 시각 없는 상담은 과거 완료 상담으로 선택하지 않습니다.
- 현재 통화의 `call_id`, 현재 `consultation_id`는 별도로 제외합니다.
- 과거 `ended_at`이 현재 통화의 최초 `started_at`보다 **엄격하게 이전**이어야 합니다.
  같은 시각/이후 저장된 상담은 제외합니다. 시간대와 소수 초 정밀도를 보존합니다.
- 연결 중인 통화는 아직 `started_at`이 없습니다. 이 경우 이미 서버에 기록된
  `updated_at`을 보수적인 cutoff로 사용합니다. 현재 시각을 새로 만들거나 시작 시각을 보충하지 않습니다.
  통화 진행/종료 상태인데 시작 시각이 없으면 안전 오류로 차단합니다.
- 최근 종료 시각 내림차순, 동일 시각이면 상담 ID 내림차순으로 1건을 선택합니다.
  쿼리부터 시간 조건을 적용하며 최대100건을 검증합니다.
- `call_id` 없이 호출하면 동일 고객/매장의 최신 메모리 통화를 먼저 사용합니다.
  메모리 통화도 없다면 해당 고객과 매장의 저장 상담 연결이 있어야 고객 정보를 조회합니다.
- 실제 DB `started_at`은 NOT NULL입니다. 과거 기록에서 예상과 달리 null이 와도
  종료 시각 기준 선택을 유지하되, 시작 시각이 있으면 유효성·종료 순서를 검사합니다.

## 과거 위험 기록 선택

선택한 최근 완료 상담 ID와 고객 ID가 일치하는 risks만 읽습니다(최대1000건).
AI 기록이 있으면 그중 최신 `created_at` 기록, 없으면 PHONE/VISIT 중 최신 기록을 선택합니다.
동일 시각이면 risk ID 내림차순입니다. 화면에 AI/전화/방문 기록 출처를 함께 표시합니다.
더 오래된 다른 상담의 위험을 가져오거나 stage별 점수/횟수를 합산하지 않습니다.
저장된 `risk_score`와 `risk_level`을 그대로 표시하며 현재 위험 정책으로 다시 계산하지 않습니다.
유효하지 않은 점수·음수/소수 횟수는 안전 오류이고 누락 횟수는 null/‘확인되지 않음’입니다.
위험 기록 자체가 없으면 ‘이전 위험 기록이 없습니다.’로 표시합니다.

DB 필드 투영:

| DB | 브리핑 DTO |
|---|---|
| profanity_count | profanityCount |
| threat_violence_count | threatCount |
| verbal_abuse_count | blameCount |
| sexual_count | sexualCount |
| shouting_count | shoutingCount |

위 이름 변환은 브리핑 표시용입니다. 기존 n8n signals/scores 계약은 변경하지 않습니다.

## 개인정보와 공개 접근

일반 공개 실제 데이터 API와 고객 지정 체감가의 `REAL_DATA_ACCESS_RESTRICTED` 보호는 유지합니다.
새 live briefing만 공개 환경의 서버 `KCM_DEMO_CUSTOMER_ID`와 정확히 일치하는 유효한 고객 ID를 허용합니다.
다른 고객/설정 누락/잘못된 설정은 DB 조회 전에403 `REAL_DATA_ACCESS_RESTRICTED`입니다.
프런트 allowlist, 임의 요청 헤더 또는 프록시 헤더로 접근을 허용하지 않습니다.
기존 Host/Origin/cross-site 검사와 비밀값 서버 보관 정책도 유지합니다.

먼저 고객 ID/이름/동의만 조회합니다. 미동의면 상품·요금제·상세 상담·위험 SELECT를 하지 않으며
‘비공개 고객’과 ‘고객 개인정보 동의 확인이 필요합니다.’를 반환합니다.
동의 고객의 표시명은 마스킹하며 목적/요약에는 기존 이름·연락처·이메일 마스킹 정책과 길이 제한을 적용합니다.
원본 이름의 앞뒤 공백이 달라도 목적/요약의 이름을 가립니다.
전화번호/생년월일/전문·내부 분석·키는 SELECT/DTO에 포함하지 않습니다.
이 공개 예외는 정식 직원 인증을 대신하지 않으며 일반 고객 접근으로 확대하지 않습니다.

## 내용과 화면

현재 상품/요금제는 customers의 기존 product_id/plan_id로 products/own_plans를 조회합니다.
최근 `ai_summary`가 없으면 저장 목적을 별도 표시하며 가짜 요약을 생성하지 않습니다.
요약은 최대1200자, 목적은 최대300자로 표시하며 긴 요약은3줄 미리보기/펼치기를 제공합니다.

확인된 고정 문구 `KCM AI 상담 DB 저장 테스트`, `KCM AI 상담 연동 테스트 종료`는
공통 표시 함수에서 정확히 일치할 때만 목적/요약 DTO를 null로 투영합니다.
비교 시 유니코드 NFC·앞뒤/연속 공백만 정규화하며, 실제 DB 값은 변경하지 않습니다.
일반 상담에서 ‘테스트’를 언급하거나 위 문장을 인용한 정상 요약은 그대로 유지합니다.
프런트도 같은 함수를 적용하여 이전 서버 응답의 고정 문구가 정상 요약으로 표시되지 않게 합니다.
대신 ‘확인할 수 있는 상담 요약이 없습니다.’로 안내하며, 새 요약이나 요약 확인 가이드를 만들지 않습니다.

좌측 ‘이번 통화’, 우측 ‘통화 시작 전의 완료 상담 기준’·‘이전 완료 상담’·‘이전 상담 종료’로
기록의 시점을 구분합니다. 이전 점수는 현재 점수와 별도로 조회한 기록임을 표시합니다.

응대 유의사항은 저장 위협/욕설 → 관리자 지원 필요성 → 저장 요약 확인을 우선하고
선정적 표현/고성/비난 기록을 보완하여2~4개의 짧은 문장으로 구성합니다.
이력이 없으면 현재 요청 확인과 과거/현재 신호 구분 안내를 제공합니다. LLM/실시간 판단을 추가하지 않습니다.

데스크톱 좌62%/우38%이며 모달 높이를 viewport 안으로 제한합니다.
대화와 브리핑 내부 스크롤을 사용하고 기존 모달의 닫기/키보드 접근을 유지합니다.

브리핑 실패는 현재 transcript와 위험 신호 표시를 중단하지 않습니다.
