# 실제 연결은 다음 단계에서

현재는 `DashboardRepository.load()`가 샘플 객체를 반환합니다.
웹의 타입 이름/필드는 실제 Supabase 테이블 이름이 아닙니다.

연결 전에 팀에서 확인할 정보:
- 고객/매장/직원/상담/예약의 실제 테이블명·컬럼명·ID 관계.
- 상담 요약·브리핑·처리 상태가 저장되는 위치와 데이터 형식.
- n8n의 저장 완료 기준과 실패/재시도 기준.
- 직원 로그인 및 조회 권한, 매장별 데이터 분리.

구현 시 교체 지점:
1. 원본 DB 행을 화면용 모델로 변환하는 어댑터를 정의합니다.
2. 승인된 인증/권한 체계에서 저장된 상담 한 건을 조회합니다.
3. 로딩/실패/빈 결과를 실제 데이터에도 유지합니다.
4. n8n이 같은 상담 ID에 저장하는 결과를 확인합니다.

웹에서 새 업무를 실행할 경우의 API는 아직 정의하거나 구현하지 않았습니다.
관리자 키·Retell API 키·n8n 인증키를 브라우저 코드에 넣지 않습니다.
`VITE_*` 설정은 브라우저에 포함되므로 비밀 키 저장소로 사용하지 않습니다.

인증, 실제 예약 확정/중복 방지, 대여·반납, 메시지 발송은
이번 샘플 화면의 상태 변경 코드를 그대로 운영용으로 사용하지 말고 별도 설계해야 합니다.
