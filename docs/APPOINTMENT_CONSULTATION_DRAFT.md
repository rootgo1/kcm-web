# 예약·상담관리 기능 명세 초안

- 작성일: 2026-09-29
- 기준 프로젝트: KCM / kcm-web 0.3.0
- 상태: **핵심 결정 반영 — 1차 상담 처리 범위·혼합 접수 방식·완료 후 결과 수정 확정, 나머지 세부안은 제안**
- 대상 화면: 예약·상담관리(`#/appointments`), 연결되는 홈의 예약·브리핑 영역
- 이번 작업: 사용자가 결정한 업무 규칙을 명세에 반영. 실제 구현 현황은 2절에 구분합니다.

## **1. 확정 범위와 제안 요약**

**첫 구현은 기존 샘플 예약의 ‘상담 시작 → 결과 기록 → 상담 완료’ 흐름부터 진행하며, 완료 후 상담 결과 수정도 허용합니다.** 사용자가 이 범위를 선택했습니다.

현재 검증된 목록·검색·필터·브리핑을 활용해 직원의 상담 처리 흐름을 구현하는 범위입니다. 완료 후 수정은 상담 상태를 유지하면서 기록 내용을 고치는 작업이며, 상담을 다시 시작하는 작업과 구분합니다.

**예약 접수는 혼합 방식으로 확정했습니다.** 고객이 통화 중 예약 접수를 희망하면 시스템에 바로 접수하고, 고객이 직접 예약하는 경우에도 바로 접수하는 흐름입니다. 별도 직원 승인 대기 단계를 전제로 두지 않습니다. 실제 접수 연결과 입력·중복·예약 가능 시간 검증은 후속 범위에서 설계합니다. 직원 수동 등록의 필요 여부는 별도로 정합니다.

예약 등록·일정 변경·담당자 변경·취소·미방문 처리는 다음 범위 후보로 명세합니다. 실제 데이터 저장과 로그인·권한 적용은 별도 단계입니다.

| 구분 | 의미 |
|---|---|
| 현재 구현 | 실제 `src/`에서 확인한 v0.3 동작 |
| 사용자 확정 | 1차 상담 처리 흐름, 혼합 예약 접수 방향, 상담 완료 후 결과 기록 수정 허용 |
| 1차 세부안 | 확정 범위를 구현하기 위한 필드·입력 제한·배치 등 제안. 명시적으로 확정한 규칙과 구분 |
| 2차 후보 | 확정된 혼합 접수 방향에 따라 세부 접수·운영 규칙과 포함 여부를 결정할 내용 |
| 결정 필요 | 사용자가 정해야 하는 업무 정책. 이 문서의 권장안을 확정값으로 취급하지 않음 |

## **2. 현재 구현된 기능과 한계**

| 항목 | 확인된 현재 동작 |
|---|---|
| 예약 목록 | 오늘의 가상 예약 8건을 시간순으로 표시 |
| 검색 | 고객명·상담 목적·담당 직원·시간·마스킹 연락처로 검색 가능 |
| 상태 필터 | 전체 / 방문 예정 / 상담 중 / 완료 |
| 예약 선택 | 선택한 고객의 상담 목적·희망 단말기·월 예산·브리핑 표시 |
| 검색 후 선택 | 기존 선택이 결과에서 제외되면 첫 검색 결과를 표시. 결과가 없으면 빈 안내 표시 |
| 사전 브리핑 | 준비됨 / 준비 중 / 확인 필요(실패 예시) 표시 |
| 브리핑 확인 | 준비된 브리핑만 확인 처리. 예약의 상담 상태와 별도로 관리 |
| 상세 보기 | 준비된 브리핑의 요약과 가상 사전 상담 대화를 모달로 표시 |
| 예약 상태 | 방문 예정 / 상담 중 / 상담 완료 데이터는 있으나 변경 조작은 없음 |
| 예약 등록·수정 | 안내 문구만 있고 실제 등록·수정 동작은 없음 |
| 상담 결과 | 직원이 결과를 입력하거나 저장하는 기능 없음 |
| 데이터 유지 | 같은 화면 실행 중 메모리에서 공유. 새로고침·샘플 초기화 시 원래 예시로 복원 |
| 로그인·권한 | 소현 프로필은 예시 표시. 실제 직원 인증과 접근 권한 검사 없음 |

현재 예약은 공통 날짜와 각 예약의 시간으로 구성돼 있습니다. 예약별 날짜, 상담 결과, 취소 사유, 변경 이력은 아직 정의돼 있지 않습니다.

## **3. 개발 범위**

| 단계 | 포함할 내용 | 완료 시 확인할 수 있는 일 |
|---|---|---|
| **1차 범위 확정: 상담 처리** | 기존 예약 조회, 브리핑 확인, 상담 시작, 상담 결과 임시 반영, 상담 완료, 완료 후 결과 수정·수정 이력, 홈 수치 반영 | 직원이 기존 샘플 예약 한 건을 상담 완료까지 처리하고 기록을 정정 |
| **2차 후보: 예약 운영** | 혼합 접수 흐름의 시연, 날짜별 조회, 일정·담당자 변경, 취소·미방문, 중복 경고, 예약 변경 내역. 수동 등록은 필요 여부 결정 후 포함 | 예약 접수부터 예외 처리까지 시연 |
| **후속 설계** | 실제 저장, 직원 인증, 역할별 권한, 동시 수정 처리, 외부 접수 연결 | 실제 운영에 필요한 데이터와 접근 규칙 확정 |

공통 유지 조건은 기존 디자인·폰트·좌측 8개 메뉴·상품 4개 탭·매장 2개 탭·프로필·예시 데이터 안내입니다. 필요한 조작은 기존 예약 화면과 상세 모달 안에 배치하는 것을 제안합니다.

첫 구현에는 새 패키지, 별도 메뉴, 외부 서비스 호출, 실제 연락·발송, 실제 고객 정보 입력을 포함하지 않는 안을 권합니다.

## **4. 업무 흐름과 상태**

### **4.1 기본 흐름**

```text
기존 예약 선택
    ↓
예약 정보·사전 브리핑 확인
    ↓ [상담 시작]
방문 예정 → 상담 중
               ↓
       상담 결과 입력·임시 반영
               ↓ [상담 완료]
           상담 완료
               ↓ [결과 수정]
       수정 내용·이력 반영
       (상담 완료 상태 유지)
```

**‘예약 확인’과 ‘브리핑 확인’은 직원의 작업이며, 새로운 예약 상태로 추가하지 않는 안을 권합니다.** 브리핑 확인만으로 상담 중·상담 완료로 바뀌지 않습니다.

### **4.2 1차 상태 변경 규칙 — 완료 후 수정 정책 확정**

| 현재 상태 | 조작 | 변경 결과 | 처리 조건 |
|---|---|---|---|
| 방문 예정 | 상담 시작 | 상담 중 | 선택한 예약 한 건만 변경 |
| 상담 중 | 결과 임시 반영 | 상담 중 유지 | 결과 내용만 반영 |
| 상담 중 | 상담 완료 | 상담 완료 | 결과 구분과 상담 요약 입력 필요 |
| 상담 완료 | 결과 조회·수정 | 상담 완료 유지 | 상담 결과 구분·요약·후속 연락 정보를 수정하고 변경 전후 내용·수정자·시각 기록 |

방문 예정에서 상담 완료로 직접 변경하는 기능은 첫 구현에서 보류합니다. 동일 조작을 반복해도 결과가 중복 생성되지 않도록 합니다.

브리핑이 준비 중이거나 실패한 상태여도 직원이 고객을 직접 상담할 수 있도록 **상담 시작을 막지 않는 안**을 권합니다. 준비된 브리핑을 아직 확인하지 않았다면 확인 안내를 표시하되, ‘확인 완료’를 자동 처리하지 않습니다.

### **4.3 취소·미방문·일정 변경 — 2차 후보**

| 상황 | 제안 처리 | 결정할 사항 |
|---|---|---|
| 고객이 방문 전 취소 | 방문 예정 → 취소, 사유 기록 | 취소 사유 필수 여부, 취소 후 복원 허용 여부 |
| 예약 시간 이후 고객 미방문 | 직원이 방문 예정 → 미방문으로 변경 | 몇 분 이후 처리 가능한지, 재방문 시 복원 방식 |
| 일정 변경 | 예약 식별자는 유지하고 일시 변경 | 변경 가능 상태와 시간, 변경 사유 필요 여부 |
| 상담 중 중단 | 첫 구현에서는 상태 추가 보류 | 중단 상태가 필요한지, 상담 결과로 구분할지 |

취소·미방문은 시간 경과만으로 자동 처리하지 않는 안을 권합니다. ‘일정 변경’은 처리 이력으로 남기고 독립 상태로 만들지 않는 안입니다. 복원·재개 정책을 확정하기 전에는 해당 조작을 구현하지 않습니다.

## **5. 필요한 정보**

### **5.1 예약 정보**

아래 표는 화면에서 필요한 정보의 초안입니다. 데이터베이스 테이블이나 필드 설계를 확정하는 문서는 아닙니다.

| 정보 | 현재 | 제안과 결정 사항 |
|---|---|---|
| 예약 식별자 | 있음 | 시스템이 구분하는 값. 직원 직접 편집 제외 |
| 고객명 | 가상 이름 | 기존 값을 표시. 2차 등록에서 필수 입력을 제안 |
| 연락처 | 마스킹된 가상 번호 | 1차는 조회만. 2차도 시연용 예시를 사용하고 필수 여부는 결정 |
| 예약 일시 | 공통 날짜 + 예약별 시간 | 1차는 오늘의 예시 유지. 날짜별 운영은 2차에 예약별 날짜와 함께 설계 |
| 상담 목적 | 있음 | 2차 등록 시 필수 제안. 선택 목록과 자유 입력의 병행 여부 결정 |
| 담당 직원 | 이름으로 표시 | 1차는 기존 담당자 유지. 2차 변경 시 우리 매장 직원만 선택하는 안 |
| 희망 단말기·월 예산 | 있음 | 선택 정보. 모르는 경우 ‘미정’ 표시 가능하도록 제안 |
| 접수 경로 | 없음 | 통화 중 시스템 즉시 접수 + 고객 직접 예약 즉시 접수의 혼합 방식 확정. 실제 연결은 후속 단계 |
| 직원 메모 | 없음 | 2차 후보. 고객에게 보여 줄 문구와 내부 메모를 구분할지 결정 |

고객명이나 마스킹된 연락처만으로 동일 고객을 자동 병합하지 않습니다. 같은 직원·같은 시작 시각의 예약이 있어도 상담 소요 시간과 동시 상담 정책을 모르는 상태에서는 중복 가능성 안내까지만 제안합니다.

### **5.2 상담 결과 — 1차 제안**

| 정보 | 상담 완료 시 필수 제안 | 입력 방식 |
|---|---|---|
| 상담 결과 구분 | 필수 | 안내 완료 / 추가 확인 필요 / 고객 검토 중 / 기타 중 선택. 명칭은 검토 필요 |
| 상담 요약 | 필수 | 직원이 직접 작성. 앞뒤 공백을 제거한 후 1~1,000자 제안 |
| 후속 연락 필요 | 필수 선택 | 필요 없음 / 필요 / 미정. 초기값은 미정 |
| 후속 연락 메모 | 선택 | 필요할 때 남기는 메모, 최대 500자 제안. 알림·발송은 실행하지 않음 |
| 상담 시작·완료 시각 | 자동 | 해당 조작을 실행한 시각. 화면은 한국 시간 기준 |

**‘상담 완료’는 매장에서 직원과 고객의 이번 상담을 마치고 결과를 기록한 상태입니다.** 예약 접수와 사전 통화 종료는 별도 단계이며, 개통·판매 여부도 구분합니다. 상담 완료 후에도 추가 확인이나 후속 연락이 남아 있을 수 있습니다.

임시 반영은 필수 항목이 덜 채워져 있어도 허용하되 글자 수 제한은 적용하는 안입니다. 상담 완료 시에는 누락 항목을 표시하고 상담 중 상태를 유지합니다.

### **5.3 상담 완료 후 기록 수정 — 확정 정책과 처리 세부안**

**상담 완료 후에도 결과 기록을 수정할 수 있도록 확정합니다.** 적용 대상은 상담 요약, 상담 결과 구분, 후속 연락 필요 여부와 메모입니다. 예약 일시·고객 정보 변경과 상담 재개는 별도 범위입니다.

| 항목 | 규칙 |
|---|---|
| 상담 상태 | 결과를 수정해도 상담 완료 유지 |
| 최초 완료 시각 | 유지. 수정 시각과 별도로 표시 |
| 수정 이력 | 변경 전후 내용, 수정자, 수정 시각을 남겨 변경 경위 확인 |
| 수정자 표시 | 1차 시연에서는 현재 샘플 사용자 표시값 사용. 실제 로그인으로 확인된 작성자 정보와 구분 |
| 홈 집계 | 기록 정정으로 완료 건수·방문 예정·상담 중 건수가 바뀌지 않음 |
| 예약·브리핑 | 결과 정정으로 예약 기본 정보나 사전 브리핑 원문·확인 상태를 바꾸지 않음 |

다음은 구현 시 적용할 처리 세부안입니다.

- ‘결과 수정’으로 기존 내용을 불러오고 ‘수정 내용 반영’으로 변경을 적용합니다.
- 완료 기록 수정에도 상담 완료 시의 필수값·글자 수 제한을 적용합니다. 오류가 있으면 기존 기록과 이력을 유지하고 입력을 고칠 수 있게 합니다.
- 수정 내용을 반영할 때 결과 변경과 이력 추가를 함께 처리합니다. 변경이 없거나 닫기에서 변경 버리기를 선택하면 이력을 추가하지 않습니다.
- 같은 탭에서 여러 번 수정하면 각 변경 이력을 순서대로 보존합니다. 과거 이력의 직접 편집·삭제 기능은 포함하지 않습니다.
- 기존 완료 샘플에 결과가 없는 경우에는 기록 없음으로 표시하고, 결과 입력 시 ‘기존 기록 없음 → 입력한 내용’으로 이력을 남기는 안입니다. 과거 상담 내용이나 완료 시각을 임의로 만들어 넣지 않습니다.

수정 이력도 1차에서는 메모리에만 유지됩니다. 영구적인 변경 기록과 실제 계정에 기반한 권한 검사는 실제 저장·인증 단계에서 적용합니다.

## **6. 화면별 동작 — 1차 제안**

| 영역 | 제안 동작 |
|---|---|
| 예약 목록 | 기존 열·검색·필터 유지. 상태 변경 결과 즉시 표시 |
| 사전 브리핑 | 기존 준비 상태·확인 버튼 유지. 실제 자동 분석이나 자동 요약을 추가하지 않음 |
| 상담 처리 조작 | 기존 예약 화면에 ‘상담 시작’, ‘상담 결과’, ‘상담 완료’ 조작을 필요한 상태에서 표시 |
| 상담 결과 입력 | 기존 모달 형식으로 입력 영역 제공. 결과 임시 반영과 상담 완료를 구분 |
| 상세 보기 | 가상 사전 상담 내용과 직원이 작성한 시연 결과를 서로 다른 항목으로 표시 |
| 미반영 입력 | 입력 후 닫기·예약 선택·메뉴 이동 시 유지 여부를 확인. ‘계속 작성’ 또는 ‘변경 버리기’로 구분 |
| 빈 검색 결과 | 기존 안내와 검색 조건 초기화 유지. 이전 고객의 상세 정보가 남지 않도록 처리 |
| 완료된 예약 | 결과 조회·수정과 수정 이력 확인 제공. 상담 완료 상태 유지 |

‘상담 결과’ 조작은 브리핑의 준비 여부와 무관하게 접근할 수 있어야 합니다. 현재 ‘상세 보기’가 준비된 브리핑에만 표시되는 동작을 그대로 결과 입력의 접근 조건으로 사용하면 안 됩니다.

검색·필터로 선택 예약이 목록에서 제외되면 기존처럼 첫 결과를 선택하되, 미반영 입력이 있으면 먼저 처리합니다. 상태 변경으로 현재 필터에서 예약이 사라지는 경우에는 결과 입력창을 먼저 정상 종료하고, 변경 완료 안내와 함께 선택을 갱신하는 안입니다.

## **7. 일관성과 저장 범위 — 1차 제안**

**1차는 같은 브라우저 탭 안에서만 유지되는 시연입니다. 새로고침·탭 닫기·샘플 초기화 시 변경 내용이 사라집니다.** 실제 저장 기능이 준비되기 전에는 이를 화면에서 명시합니다.

‘결과 임시 반영’ 후에는 같은 탭에서 다른 메뉴로 이동했다가 돌아와도 입력한 결과가 유지돼야 합니다. 반영 전 입력창을 떠날 때의 확인과, 새로고침에 따른 전체 초기화는 구분합니다.

| 연결 항목 | 일관성 기준 |
|---|---|
| 홈 ↔ 예약·상담관리 | 동일 예약의 상태와 결과를 같은 데이터로 표시 |
| 오늘의 예약 건수 | 1차는 등록·삭제가 없으므로 상태 변경으로 총건수가 바뀌지 않음 |
| 방문 예정 → 상담 중 | 방문 예정 1 감소, 상담 중 1 증가 |
| 상담 중 → 상담 완료 | 상담 중 1 감소, 완료 1 증가 |
| 완료 후 결과 수정 | 상담 상태·최초 완료 시각·예약 집계 유지, 변경 내용과 수정 이력만 반영 |
| 브리핑 확인 여부 | 상담 상태와 독립적으로 유지. 상담 완료 시 자동 확인 처리하지 않음 |
| 브리핑 확인 대상 건수 | 1차는 기존 계산 유지: 준비된 브리핑 중 미확인인 예약 수. 완료 상태를 자동 제외하지 않음 |
| 최근 업무 흐름 | 홈의 기존 샘플 기록 유지. 상담별 결과 수정 이력은 1차에 제공하고, 홈 업무 흐름에 자동 표시하는 기능은 2차 후보 |
| 다른 예약 | 한 예약의 수정이 다른 예약의 상태·결과를 바꾸지 않음 |

2차에서 날짜·취소·미방문을 도입할 때는 당일 집계와 활성 예약의 의미를 함께 확정해야 합니다. 예를 들어 총 접수 건수에 취소를 포함할지, 브리핑 확인 대상에서 종료된 예약을 제외할지는 별도 결정입니다.

상담 목적·희망 단말기 등을 수정하는 2차 기능에서는 이전 브리핑을 최신 정보처럼 표시하지 않아야 합니다. ‘브리핑 없음’·‘내용 변경 후 재확인 필요’ 상태가 필요한지도 함께 설계합니다. 입력값 수정만으로 실제 분석이나 요약 생성이 수행되는 것처럼 표시하지 않습니다.

## **8. 입력 오류와 예외 처리 — 제안**

| 상황 | 기대 동작 | 적용 범위 |
|---|---|---|
| 결과 구분·요약 누락 후 완료 | 누락 항목 안내, 기존 입력 유지, 상담 중 상태 유지 | 1차 |
| 글자 수 초과 | 해당 입력칸에 오류 표시, 내용을 자동 삭제하지 않음 | 1차 |
| 완료 버튼 연속 조작 | 한 번만 완료 처리, 중복 결과 없음 | 1차 |
| 브리핑 준비 중·실패 | 현재 상태 안내, 상담 시작과 결과 입력은 가능 | 1차 |
| 다른 예약을 선택 | 미반영 입력이 있으면 확인 후 이동 | 1차 |
| 완료된 상담 결과 수정 | 수정 가능. 완료 상태·최초 완료 시각·집계를 유지하고 수정 이력 추가 | 1차 |
| 완료 결과 수정 시 필수값 누락 | 반영 차단, 기존 결과·이력·완료 상태 유지, 입력 오류 안내 | 1차 |
| 새로고침·샘플 초기화 | 초기 예시로 복원. 시연 중 데이터가 사라짐을 명확히 안내 | 1차 |
| 동일 직원·동일 시작 시각 | 중복 가능성 안내. 강제 차단 여부는 운영 정책 결정 후 적용 | 2차 |
| 과거 일시 예약 입력 | 신규 예약 기준으로 차단 제안. 과거 기록 입력 필요 여부 결정 | 2차 |
| 취소·미방문 후 재예약 | 기존 예약 복원 또는 새 예약 생성 중 정책 결정 필요 | 2차 |

향후 실제 저장을 연결할 때는 저장 실패 시 성공 안내를 표시하지 않고, 입력값을 보존하며 재시도를 제공해야 합니다. 여러 직원의 동시 수정, 수정 이력의 영구 보관, 실제 계정에 기반한 수정자 확인과 권한 적용도 그 단계에서 다룹니다.

## **9. 첫 구현의 완료 기준 — 구현 후 검증할 항목**

아래 항목은 새 기능의 검수 시나리오입니다. **현재 통과한 기존 40개 테스트와 별개이며, 아직 구현·실행하지 않았습니다.**

| 번호 | 검증 시나리오 | 통과 기준 |
|---|---|---|
| A01 | 방문 예정 예약에서 상담 시작 | 해당 예약만 상담 중으로 변경되고 홈 수치도 일치 |
| A02 | 준비 중·실패 브리핑의 예약에서 상담 시작 | 상담 시작 가능, 브리핑을 임의로 준비 완료 처리하지 않음 |
| A03 | 상담 결과 임시 반영 후 메뉴 이동·복귀 | 같은 탭에서 내용 유지, 예약은 상담 중 유지 |
| A04 | 필수값을 비운 채 상담 완료 | 입력 오류 표시, 내용 보존, 상태와 완료 시각이 바뀌지 않음 |
| A05 | 결과 구분·요약 입력 후 상담 완료 | 결과와 완료 시각이 반영되고 목록·홈의 상태 및 건수 일치 |
| A06 | 완료 버튼 반복 조작 | 결과 중복 생성과 중복 집계 없음 |
| A07 | 미반영 결과를 둔 채 닫기·다른 예약·메뉴 선택 | 계속 작성하면 입력 유지, 변경 버리기를 선택해야 폐기 |
| A08 | 현재 상태 필터에서 예약 상태 변경 | 입력창이 정상 종료되고 목록·선택·브리핑이 서로 일치 |
| A09 | 완료 예약에서 결과 조회·수정 | 결과를 수정할 수 있고, 상담 완료 상태·최초 완료 시각·홈 집계는 유지 |
| A10 | 새로고침·샘플 초기화 | 원래 가상 데이터로 복원, 실제 저장됐다는 오해를 주지 않음 |
| A11 | 기존 메뉴·탭·프로필·브리핑 확인 | 기존 동작 유지, 브리핑 확인과 상담 완료가 서로 독립적 |
| A12 | 1366×768 및 키보드 조작 | 좌측 메뉴 잘림 없음, 입력·확인·닫기·초점 이동 가능 |
| A13 | 완료 결과를 두 번 수정 | 각 수정의 변경 전후 내용·샘플 수정자·시각이 이력에 남음 |
| A14 | 완료 결과 수정 시 필수값 삭제·길이 초과 | 오류 표시, 기존 결과·이력·완료 상태 보존 |
| A15 | 완료 결과에서 변경 없이 반영 또는 변경 버리기 | 결과와 이력이 불필요하게 바뀌지 않음 |
| A16 | 기록 없는 기존 완료 샘플에 결과 입력 | 기록 없음 상태를 명시하고 최초 입력 이력 생성, 과거 내용·완료 시각을 임의 생성하지 않음 |

구현 시 기존 단위 테스트와 전체 타입 검사·빌드는 `npm.cmd run check`로 확인하고, 새 상태 변경과 입력 검증에는 필요한 테스트를 추가합니다. 소스를 수정한 경우 `npm.cmd run preview:standalone`으로 독립 미리보기도 갱신합니다.

## **10. 사용자 결정과 남은 세부안**

아래 세 가지는 사용자 답변을 반영한 확정 사항입니다. 같은 사항을 다시 미확정으로 취급하지 않습니다.

| 항목 | 사용자 결정 | 적용 범위 |
|---|---|---|
| **첫 구현** | 위 상담 처리 흐름부터 시작 | 기존 예약의 상담 시작·결과 기록·완료 및 완료 후 결과 수정 |
| **예약 접수** | 혼합 방식. 고객이 통화 중 예약을 희망하면 시스템에 바로 접수하고, 고객이 직접 예약해도 바로 접수 | 후속 접수 설계의 기준. 실제 외부 연결 작업은 별도 범위 |
| **완료 기록** | 상담 완료 후에도 결과 기록 수정 허용 | 상담 요약·결과 구분·후속 연락 정보 수정, 완료 상태 유지, 변경 전후 내용·수정자·시각 기록 |

추가로 조정할 수 있는 1차 세부안은 상담 결과의 선택지, 완료 시 요약 필수 여부, 글자 수 제한, 브리핑 미확인 상태에서도 상담 시작을 허용하는 규칙입니다. 이 문서의 해당 제안을 기준으로 검토할 수 있습니다.

2차 착수 전에는 연락처 필수 여부, 담당자 미배정 허용, 취소·미방문 기준, 날짜별 조회, 상담 소요 시간과 중복 기준, 완료·취소 예약의 집계 방식을 추가 확정합니다.
